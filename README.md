# Timing-Driven VLSI Router

A C++-based educational VLSI routing project that integrates static timing analysis with physical design to prioritize timing-critical connections.

The project reads structural Verilog, LEF cell geometry, placement information, and critical-net data generated by a separate Python Static Timing Analyzer (STA).

## Project Overview

Physical routing connects the pins of placed standard cells while respecting geometric constraints. Routing decisions can affect wire length, congestion, and ultimately circuit timing.

This project aims to develop a timing-driven grid router that prioritizes critical signal paths before routing less timing-sensitive connections.

## Current Features

- **Structural Verilog Parsing:** Extracts standard-cell instances, pin connections, and net connectivity.
- **LEF Parsing:** Reads cell dimensions and pin geometry.
- **Placement Processing:** Loads standard-cell coordinates from a placement file.
- **Grid Representation:** Models the chip as a 2D grid containing placed cells and routing obstacles.
- **Pin Access Generation:** Calculates routing access coordinates for standard-cell pins.
- **Net Grouping:** Identifies the pins belonging to each electrical net.
- **STA Integration:** Imports critical-net information generated by a separate Python STA project.

## Planned Features

- Dijkstra's shortest-path routing algorithm.
- Routing critical connections before noncritical connections.
- Multi-terminal net routing.
- Wire-length and congestion calculations.
- Routing conflict detection and improved obstacle handling.
- More detailed timing-driven optimization.

## How It Works

1. Parse structural Verilog to identify instances and connected nets.
2. Read LEF definitions to obtain cell dimensions and pin positions.
3. Load placement coordinates and calculate absolute pin locations.
4. Represent standard-cell footprints as blocked regions on a routing grid.
5. Generate accessible routing points for each cell pin.
6. Import timing-critical net names from the Python STA.
7. Use the resulting connectivity, geometry, and timing information as the foundation for timing-driven routing.

## Building and Running

**Requirements:** Linux/Ubuntu and a C++ compiler such as `g++`.

Compile:

```bash
g++ router.cpp -o router
```

Run:

```bash
./router
```

The current implementation expects a `critical_nets.txt` file generated by the Python STA. Update the input path in `router.cpp` to match the location of that file.

## Static Timing Analysis Integration

The companion Python STA project calculates register-to-register timing paths using structural Verilog, Liberty timing data, and SDC clock constraints.

The STA identifies the critical path and exports its net names to `critical_nets.txt`.

Example:

```text
q1
n1
n3
n4
n8
e_internal
```

The router reads this file to identify timing-sensitive nets. Future routing stages will use this information to establish routing priorities, including distinguishing timing-critical branches on multi-terminal nets.

## Current Limitations

This is an educational prototype rather than a production-ready physical-design router.

- Routing is currently represented on a simplified 2D grid.
- Standard-cell interiors are treated as routing obstacles.
- The current pin-access model uses simplified left/right access points.
- Shortest-path search and wire routing are not yet implemented.
- Detailed design-rule checking and multilayer routing are not yet supported.

## Development Goals

The long-term objective is to connect static timing analysis with physical routing decisions, allowing the router to prioritize connections with the greatest timing sensitivity and evaluate the effects of routing on physical wire length and timing.
